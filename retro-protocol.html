Протокол
ретрокаталогізації

Як читати архівний матеріал, виявляти приховані зв'язки і збагачувати граф знань — червень 2026

Концепт Що таке ретрокаталогізація і чому вона інша

Ретрокаталогізація — це не редагування опублікованих матеріалів. Це виявлення прихованих зв'язків між уже наявними матеріалами і вже наявними картками сутностей. Матеріал в архіві залишається незмінним. Змінюються картки: діяч отримує нову подію в таймлайні, твір — цікавинку, PDF-картка — питання для дискусії.

Аналогія: бібліотекар переглядає старий картковий каталог і проставляє предметні рубрики, яких раніше не було. Самі картки не переписуються — вони збагачуються.

Розділ 1 Покроковий протокол сесії
1

Обрати матеріал для обробки

Відкрити таблицю стану міграцій. Взяти перший матеріал зі статусом не оброблено. Пріоритет: ювілейні есе → рецензії → дослідницькі статті → решта.

Не обирати матеріали довільно — рухатись за таблицею щоб не було «білих плям» і повторів.

2

Прочитати матеріал цілком, не вносити ще нічого

Перше читання — аналітичне. Тримати в голові питання: які сутності згадуються? Які факти прив'язані до дат? Які книги рекомендуються? Де є пряма мова автора?

Фіксувати олівцем (або в нотатках) — але не відкривати адмінку до кінця читання.

3

Заповнити протокол виявлення

Відкрити таблицю протоколу (див. розділ 2). По кожній знахідці: тип → що саме → куди вносити. Один рядок — одна знахідка.

Якщо знахідок немає — це теж результат. Позначити «перевірено, нових зв'язків не виявлено».

4

Для питань дискусії — запустити ШІ-асистент (Фаза 1)

Якщо матеріал достатньо глибокий (біографія, контекст творчості, теми) — скопіювати текст у NotebookLM або Gemini з стандартним промптом (див. розділ 3). Отримати список питань. Відредагувати.

ШІ — пропозиція, не результат. Редактор перевіряє кожне питання перед внесенням.

5

Внести знахідки в адмінку

По кожному рядку протоколу — відкрити відповідну картку і внести. У полі «Службові коментарі» завжди фіксувати: звідки взято, дата внесення, хто вніс.

Архівні поля (посада, місто, дата публікації) — не чіпати. Лише нові поля.

6

Позначити матеріал як «оброблено»

У таблиці стану міграцій змінити статус на оброблено, вписати дату і ім'я виконавця. Якщо деякі знахідки не вдалось внести (немає картки, потрібна верифікація) — статус частково + примітка.

Розділ 3 Стандартний промпт для генерації питань дискусії

Використовується в NotebookLM (завантажити матеріали про автора/твір як джерела) або в Gemini (вставити текст матеріалу напряму). Результат редагується перед внесенням у картку.

Промпт v1.0 Ти — бібліотекар-методист, що готує матеріал для читацького обговорення.
На основі наданих матеріалів про [ім'я автора / назва твору] склади список питань для дискусії з читачами.

Вимоги до питань:
– Мінімум 6, максимум 10 питань
– Питання різного рівня: фактичні (1–2), інтерпретаційні (2–3), особистісно-рефлексивні (2–3)
– Кожне питання — одне речення, без підказки відповіді
– Уникати питань із відповіддю «так/ні»
– Формулювати для аудиторії: [вік / тип аудиторії: бібліотекарі / школярі 10–14 / загальна]

Формат відповіді:
Пронумерований список. Після списку — 1–2 речення: на яких темах акцентують ці питання.

Матеріали:
[вставити текст або вказати джерела в NotebookLM]
Тип аудиторії Рівень питань Особливість формулювання
Бібліотекарі / педагоги Переважно інтерпретаційні та методичні «Як використати цей текст у роботі з…», «Що в біографії автора пояснює…»
Школярі 10–14 років Фактичні + особистісно-рефлексивні «Що б ти зробив на місці героя…», «Чи змінила тебе ця книга…»
Дорослі читачі Інтерпретаційні + контекстуальні «Як час написання вплинув на…», «Що залишається актуальним сьогодні…»
Розділ 4 · Дорожня карта Три фази ШІ-інтеграції в ретрокаталогізацію

Поточний протокол розрахований на Фазу 1. Фази 2 і 3 — зафіксовані тут як орієнтири, щоб не переробляти архітектуру потім.

Фаза 1 · Зараз

Ручний процес + NotebookLM / Gemini

Червень 2026 → до запуску Apps Script інтеграції
  • Виконавець вручну читає матеріал і заповнює протокол виявлення
  • Для питань дискусії: копіює текст у NotebookLM (корпус матеріалів про автора) або Gemini (окремий матеріал)
  • Промпт стандартизований (розділ 3 цього документа)
  • Результат редагується вручну перед внесенням у картку
  • Статуси «оброблено» ведуться в Google Sheets (спільний доступ через Workspace)
Інструменти: NotebookLM (Google Workspace for Nonprofit), Gemini, Wagtail admin, Google Sheets для таблиці статусів
Фаза 2 · Середньострокова

Google Apps Script + Gemini API — напівавтоматизація

Після стабілізації ядра порталу і UX-аудиту · орієнтовно осінь 2026
  • Apps Script отримує URL матеріалу з КЛЮЧА або текст з Google Drive
  • Викликає Gemini API зі стандартним промптом (версія промпту з розділу 3)
  • Повертає структурований протокол виявлення у Google Sheet або Google Doc
  • Редактор перевіряє → вручну вносить у адмінку
  • Таблиця статусів оновлюється автоматично після підтвердження
Що потрібно для запуску: Gemini API ключ в Workspace (або через Google AI Studio), скрипт-шаблон Apps Script (є досвід SMM-автоматизації — та сама модель). Підключення до живої БД КЛЮЧА не потрібне на цьому етапі.
Фаза 3 · Перспектива

Вбудований асистент у кабінеті бібліотекаря

Після запуску кабінету користувача і публічного API · 2027
  • Бібліотекар відкриває картку автора або твору на порталі
  • Натискає «Згенерувати питання для заходу» — обирає тип аудиторії
  • Асистент отримує дані з бази КЛЮЧА (біографія, таймлайн, рецензії, публікації) через внутрішній API
  • Повертає список питань прямо в інтерфейс — бібліотекар редагує і завантажує PDF
  • Масштаб: 15 000+ бібліотекарів мережі без участі контент-менеджера
Блокери для запуску: кабінет користувача (в беклозі), публічний API або внутрішній endpoint для асистента, рішення про модель (Gemini API / власний LLM). Архітектура API-first вже передбачає цей сценарій — переробки не потрібно.
Розділ 5 Чеклист завершення сесії ретрокаталогізації

Перед тим як закрити адмінку — перевірити:

Всі знахідки з протоколу внесено (або позначено причину чому ні)
Кожна нова сутність перевірена на дублі перед створенням
У «Службових коментарях» зафіксовано джерело і дату для кожного внесеного поля
Архівні поля (посада, місто, дата публікації) — не змінені
Питання для дискусії відредаговані (не пряма копія з ШІ)
Матеріал у таблиці статусів позначено з датою і ім'ям виконавця
Якщо виявлена нова книга або особа — заведено картку або зроблена задача для наступної сесії
